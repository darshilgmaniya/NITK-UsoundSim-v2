# Decision Log

Each entry: context, decision, alternatives, consequences. Status "accepted" unless noted. Decisions marked **confirm** need sign-off from the teams involved.

## D1 - Array size 64 to 128 elements
- Context: requested for the integration; improves lateral resolution.
- Decision: `N_ELEMENTS = 128` in `config.py`; pitch unchanged (lambda/2).
- Alternatives: also halve the pitch to keep the aperture (rejected: not requested).
- Consequences: aperture 9.7 mm to 19.6 mm; lateral FWHM 1.7x to 1.9x finer; AP cost x1.8; echo amplitude about 1.6x to 1.7x on the wire-target test (unnormalised sum). `N_SCANLINES` stays 64 (image lines, not elements).

## D2 - Monorepo with modules and integration separated
- Context: teams develop independently; integration happens step by step.
- Decision: `teams/Tn_*` (self-contained) and `integration/NN_*` (data hand-over only).
- Alternatives: one flat package (rejected: hides ownership); git submodules (rejected: overhead for student teams).
- Consequences: each module keeps its own tests and README; CI runs them separately.

## D3 - Single source of truth for the array = Acoustic Propagation `config.py`
- Decision: `make_ti_config` derives f0, c, fs, element count and pitch from it.
- Alternative: let Tissue Interaction body-part presets choose the probe (rejected: the two modules would disagree about the array).
- Consequences: Tissue Interaction preset probe settings are ignored in the relay (its phantoms still come from presets).

## D4 - Attenuation counted once, owned by Tissue Interaction by default  **confirm**
- Decision: `attenuation_owner="tissue"` -> TI `path_model="full"`, AP alpha0 = 0. Option `"ap"` reverses it.
- Alternative: apply both (rejected: double counting, shown by V5).
- Consequences: shadows and frequency-dependent attenuation appear in the echo; the uniform AP alpha0 is bypassed.

## D5 - Final baton is Acoustic Propagation part 2  **confirm**
- Decision: `received_pressure` (128, T) from AP part 2; TI stage 3 saved as an alternative.
- Alternative: TI stage 3 as the main output (kept as option; has tissue-aware delays, spreading, directivity).
- Consequences: main output uses uniform c = 1540 m/s and no directivity; the teams may switch later without changing the relay.

## D6 - Vectorised batch functions added next to, not instead of, the originals
- Decision: `forward_propagation_many`, `return_propagation_many` appended to `acoustic_propagation.py`.
- Alternative: rewrite the originals (rejected: they are the reference and have 22 tests).
- Consequences: both coexist; `test_batch_equivalence.py` locks them together (relative error under 1e-6).

## D7 - Pulse windowing and trimming thresholds
- Decision: pulses evaluated within +-5 sigma (e^-12.5); reflected waveforms trimmed at 1e-6 of peak.
- Consequences: measured speed-up over the original loops for 40 scatterers and a 40 mm deep axis: 10x (forward) and 6x (return), growing with scatterer count and time length; error about 7e-7 of peak; thresholds are parameters.

## D8 - Unfocused transmit by default, `tau_tx` as the hook
- Decision: keep Team 3's zero delays; expose `RelayConfig.tau_tx`.
- Alternative: implement focusing here (rejected: belongs to the Transmit Beamforming team).

## D9 - Files as `.npz` with self-describing keys
- Decision: NumPy archives with shape meaning, units and row labels stored beside the data.
- Alternatives: HDF5 (extra dependency), CSV (too large). Consequences: easy loading in Python, Colab and MATLAB (via Python).

## D10 - Check beamformer lives in `verify.py` and is labelled QA only
- Decision: a minimal delay-and-sum for tests; the Receiver Beamforming team owns the real one.

## D11 - Documentation as code
- Decision: all documents are Markdown in `docs/`, numbers regenerated by `verification/run_verification.py`, one PDF report built from them.
